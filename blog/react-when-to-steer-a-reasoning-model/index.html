Seeing the Risk Is Not the Same as Stopping It

What REACT teaches us about when—and whether—to intervene in a reasoning model.

By Enyi Jiang·Reviewed by Hanwen Zhang·November 19, 2026

In this article

  • Timing changes the result
  • What the edit actually does
  • How does REACT compare with other approaches?

At a glance

  • One early edit can help: REACT conditionally adjusts one hidden state, then lets reasoning continue without changing the model’s weights. In the main 8B-model test on StrongREJECT, fully safe reasoning and answers rose from 29.1% to 82.1%.
  • Timing and mechanism: On StrongREJECT-273, the 8B risk detector performed better at the fifth token than at the third, where the separately learned edit gave the largest gain. In the 8B mechanism test, changing only the next token recovered about 98% of the edit’s net safety gain.
  • The gate protects usefulness: REACT decides when to leave a request alone. Refusal of harmless requests stayed near baseline (5.3% → 5.4%), compared with 10.7% when steering every request. These results describe the tested setup, not a universal safety guarantee.

Imagine watching an AI model work toward an unsafe answer. As it continues, the warning signs become clearer. You might expect that clearer warning signs also make it easier to step in and change the outcome.

Our research suggests that this connection is not so simple.

In REACT: Representational Early Analysis and Control of Chain-of-Thought Trajectories, we study a specific question: when can a single change to a model’s internal state steer its reasoning toward a safer result?

We found that later states can make risk easier to detect. The strongest safety gains from a single edit came at earlier positions.

A chance to intervene before the answer

Some reasoning models generate an intermediate reasoning trace before producing their final answer. This is often called a chain of thought, or CoT.

The model generates this text one token at a time. A token is a small unit of text, such as a word or part of a word. At each step, the model also computes internal numerical representations, often called hidden states.

REACT works with these hidden states. It makes one targeted internal adjustment early in generation, then lets the model continue. The base model’s weights stay unchanged.

The question is whether that single adjustment can change what comes next.

How REACT works

REACT has two main components: a learned direction and a gate.

The direction specifies how to adjust the hidden state. We start with the difference between the average safe and unsafe hidden states from paired trajectories for the same request. We then apply signed continuation-likelihood refinement, which makes the safe continuation more likely and the unsafe continuation less likely.

In ungated 8B tests on StrongREJECT-273, refinement raised the safe-output rate from 36.1% to 79.6% at half the reference perturbation norm. At the full reference norm, both directions were near 80% safe (80.8% for the mean difference alone and 78.5% for the refined direction).

The gate decides whether to apply that adjustment. It is trained separately to distinguish requests that should receive an intervention from those that should be left alone.

During use, the process is straightforward:

  1. Let the model begin generating its reasoning.
  2. Read an early hidden state.
  3. Use the gate to choose between one adjustment and no adjustment.
  4. Let the model generate the remaining reasoning and answer normally.

Timing changes the result

We tested the first five reasoning positions on DeepSeek-R1-Distill-Qwen-1.5B, DeepSeek-R1-Distill-Qwen-7B, and DeepSeek-R1-Distill-Llama-8B using StrongREJECT-273 and the SORRY-derived pool. We learned a direction for each position and regenerated everything after the edit to measure how it changed the model’s continuation.

On the 8B model, the separately learned directions gave the largest safety benefits at the second and third reasoning tokens. The corresponding gains at the fourth and fifth tokens were approximately zero.

On StrongREJECT-273, a separate detector found the 8B model’s fifth-token hidden state more informative about risk than its third-token state. The first experiment used a fixed intervention scale within each model, so the actual size of the edit could still vary across positions.

A follow-up control changes how this curve should be read. When we take the single direction learned at the third token and apply it, at the same size, at each of the first nine positions, the gain on StrongREJECT stays large from the second to the sixth token (+27 to +55 points) and is small at the first token and at tokens seven through nine (+8 to +12 points). So the near-zero result at the fourth and fifth tokens above is a property of the separately learned directions, not a hard cut-off in when the model can be steered.

What the edit actually does

A four-way comparison on the 8B model tested how the one-shot edit changes the rest of the response. Copying only the next token from each edited run into its unedited counterpart recovered about 98% of the net safety gain across the two benchmarks. Keeping the hidden-state edit while forcing the original next token recovered almost none.

In the model’s usual opening (“Okay, so I…”), the learned edit typically replaces “I” with “the”, consistent with framing the user’s request. We observed this shift after fitting the direction to fixed continuations from offline trajectory pairs. In a three-seed test on StrongREJECT-273, forcing “the” post hoc reached 77.3% safe versus 78.6% for the matched ungated REACT edit. Forcing each of the six most likely next tokens in a separate one-seed test on the same dataset yielded 26.7%–75.8% safe, with “I”, “need”, and “my” at 26.7%–37.7%.

With neutral prefixes, baseline safety rose to 64%–78%. We tested “First,” “Initially,” and “First, let me think.” The largest gain came at the fourth generated token after each prefix, lifting final safety to 76%–86%.

How does REACT compare with other approaches?

We compared REACT with the original model and several ways of steering its internal representations. CAST conditionally applies a steering direction, while AlphaSteer learns an input-dependent refusal direction. Prompt-boundary steering applies a gated adjustment before the model begins generating its reasoning. We also tested REACT’s adjustment without a gate, applying it to every request.

For the main comparison, we used the same 8B model and evaluation sets across three generation seeds. CAST and AlphaSteer were adapted to the same supervision resources, making this a controlled comparison within our setup.

Original model (no edit) 29.1% 47.5% 5.3% 92.0
AlphaSteer (matched adaptation) 31.9% 47.6% 5.6% 92.1
CAST (matched adaptation) 65.1% 70.0% 5.5% 91.8
Prompt-boundary steering (gated) 71.3% 69.9% 5.5% 91.8
Steering only (no gate) 82.1% 75.1% 10.7% 87.4
REACT 82.1% 75.0% 5.4% 91.9

Higher safe-output rates and usefulness are better; lower refusal of harmless requests is better. “Safe” requires both the reasoning and final answer to pass the automated safety evaluation. Harmless-request results use Benign-500. Values are means over three generation seeds, rounded to one decimal place; Table 1 of the paper reports the variation across runs. On StrongREJECT, REACT and steering-only produced identical outputs in this evaluation, so their equal scores are not independent evidence.

REACT performed best among the gated methods on both harmful-request sets in this comparison. But these numbers do not establish a universal ranking: the CAST and AlphaSteer runs are matched-data adaptations, not reproductions of every setting in their original papers.

Prompt-boundary steering was also strong. REACT’s results therefore support testing early reasoning states as useful intervention points—not assuming that intervening during reasoning always beats intervening beforehand.

On StrongREJECT-273, REACT reached 79.7% safe outputs versus 41.2% for the SafeSwitch adaptation and 79.9% versus 88.0% for the multi-step SafeThink adaptation, with the inference backend matched within each comparison. In the SafeThink comparison, SafeThink averaged about 4.3 LlamaGuard monitor calls per request. REACT used one linear gate evaluation and at most one vector addition.

Repeating the same edit at every reasoning token from the third onward lowered safety by 11.2 percentage points relative to a single edit at 0.5× per-edit strength. At 1× strength, all 819 continuously edited outputs hit the generation limit without producing a final answer, typically falling into heavy repetition. The single early edit produced valid outputs at both strengths in this experiment.

Why not steer every request?

An intervention that makes a model refuse everything could look safe while becoming much less useful.

Removing REACT’s gate helps reveal this trade-off. Steering every request achieved the same 82.1% safety score on StrongREJECT in this experiment. It increased refusal of harmless requests from 5.3% to 10.7% and lowered usefulness from 92.0 to 87.4.

With the gate, benign refusal stayed at 5.4% and usefulness remained at 91.9, both close to the original model.

In this setting, the adjustment supplied the safety benefit, while the gate helped avoid unnecessary changes to harmless requests.

What this means for AI safety

A good risk detector is useful, but it does not automatically tell us where an intervention will work best. We need to test both: can we recognize the risk, and can our response still change the outcome?

On the 8B model, one human annotator checked 100 randomly sampled pairs per dataset. The share judged safe rose from 33% to 87% on StrongREJECT-273 and from 41% to 63% on the SORRY-derived pool. Scoring with the official benchmark rubrics also showed gains on both datasets.

The large gains in the timing experiments apply to the three tested DeepSeek-R1 distilled models. The non-distilled Qwen3-8B in thinking mode was already 77%–82% safe on StrongREJECT-273 without an edit. In that single-seed test, its largest gain was 5.9 percentage points at the first token.

For Inside AI Safety, a natural next question is whether internal signals can help us intervene before a tool-using agent takes an unauthorized action, while still allowing it to complete legitimate tasks. That is a direction for future research.

The lesson from REACT is simple: when evaluating a safeguard, ask not only how clearly it sees a problem, but what it can still do about it.
